# 无法开机

<Badge text="先停手" type="danger" /> <Badge text="按启动阶段判断" type="warning" /> <Badge text="保留原厂镜像" type="tip" />

“无法开机”可能是启动镜像错误、内核不兼容、驱动 panic、启动脚本卡死或某个应用导致系统界面无法完成启动。处理顺序取决于设备停在哪一步；在不知道故障层级时连续刷入第二个、第三个包，只会扩大受影响范围。

::: danger 不要再叠加未知改动

设备已经无法进入系统时，不要继续安装模块、切换 Root 方案、尝试不同 `.ko` 或刷入来源不明的 AnyKernel3。先确认能进入 Fastboot、Recovery 还是 Android，再按对应阶段处理。

:::

## 先看设备停在哪里

:::: table 启动阶段与常见来源

| 现象 | 已经完成了什么 | 更可能的故障层 |
| --- | --- | --- |
| 按电源键完全没有反应，或连 Bootloader 标志都不出现 | 可能尚未进入正常启动链 | 电量、硬件、Bootloader、按键或完全损坏的启动分区 |
| 能看到厂商标志或 Bootloader，但进不了内核启动画面 | Bootloader 已加载启动镜像 | 错误的 `boot`、`init_boot`、`vendor_boot`、槽位或内核镜像 |
| 能看到系统启动动画，随后循环 | 内核和 Android `init` 已经开始 | 启动脚本、模块挂载、SELinux、内核模块或系统服务 |
| 能进入锁屏，但桌面、系统界面或目标应用反复崩溃 | Android 已基本启动 | 模块文件注入、应用 Profile、内置能力或应用自身数据 |
| 能进入系统，但 Root、模块或某个能力不可用 | 系统与驱动可能已经启动 | 管理器身份、授权、用户态服务或能力配置 |

::::

==启动动画出现通常说明 Linux 内核已经被启动==，但这不等于 FinaSU 驱动、`ksud` 和所有模块都正常。反过来，启动动画之前就卡住时，音量键安全模式通常没有机会运行。

:::: timeline 从故障发生到安全恢复

- 确认设备停在 Bootloader、启动动画还是系统界面
  time=观察 type=warning

- 停止继续刷入未知模块或镜像，记录最后一次改动
  time=止损 type=danger

- 启动动画阶段优先尝试 FinaSU 安全模式
  time=恢复 type=tip

- 启动镜像阶段按实际修改的分区刷回原厂镜像
  time=救援 type=warning

- 系统恢复后再逐项验证 Root、模块、Zygisk 和 Sui
  time=验证 type=success

::::

## 三种安装方式的风险位置

::::: field-group

:::: field LKM
@type `持久安装`
修补启动镜像的 ramdisk，通常写入 `init_boot`，没有 `init_boot` 时写入 `boot`。KMI 不匹配、分区错误或槽位错误会让内核在启动早期失败。
::::

:::: field Built-In
@type `持久安装`
把驱动编入 Linux 内核，通常刷入完整 `boot`。内核源码、配置、版本、AnyKernel3 包或分区不匹配时，设备可能在启动动画前就失败。
::::

:::: field 越狱模式
@type `当前会话`
不修改启动分区，在 Android 启动后加载模块。普通重启会清除这次加载；如果模块加载导致崩溃，重启后通常不会再自动加载，但它仍可能让当前会话突然重启或黑屏。
::::

:::::

::: warning “没有改 boot”不等于绝对安全

越狱模式不写入持久启动链，但它仍在运行中的内核里执行高权限模块。错误 KMI、错误架构或内核接口不兼容仍可能让当前系统崩溃。恢复时不要误刷一个与当前系统不匹配的镜像。

:::

## 尝试 FinaSU 安全模式

持久安装时，FinaSU 会在启动早期统计音量减键的按下事件。达到 **3 次** 后，本次启动会被判定为 FinaSU 安全模式。

:::: steps

1. **从设备开始启动时准备**

   在厂商标志出现后、系统进入较晚启动阶段前，连续执行三次“按下音量减键并松开”。每次都要有明确的按下动作。

2. **等待进入系统**

   不要因为一次没触发就连续按住几十次。FinaSU 在达到条件后会停止早期输入监听，继续按键不会改变已经作出的判定。

3. **确认安全模式**

   管理器首页应显示安全模式状态。Android 自身也可能进入安全模式，表现为第三方应用暂时不可见，这两者不要混淆。

4. **处理可疑模块**

   FinaSU 安全模式会跳过模块启动脚本、Folk Mount、FolkZygisk、Sui 等启动流程，并禁用普通模块和受管内核模块。进入系统后一次只重新启用一个模块，每次重启验证。

::::

安全模式不是“撤销已经写入内核的坏代码”。如果驱动根本没有加载、内核在音量键监听前崩溃，或者启动镜像本身错误，音量键流程不会生效。

::: important 延迟加载不适用音量键安全模式

越狱模式没有持久启动补丁，也没有启动阶段输入监听。此时不要反复按音量键期待 FinaSU 安全模式出现；应先正常重启清除本次延迟加载，再检查导致崩溃的载荷和内核匹配。

:::

## Android 安全模式与预初始化保护

`ksud` 还会识别系统属性 `persist.sys.safemode=1` 或 `ro.sys.safemode=1`。因此，一些 ROM 通过 Recovery 或按键进入 Android 安全模式时，也会跳过 FinaSU 的模块启动流程。

模块预初始化还有独立的连续失败保护：

- 连续多次启动没有完成预初始化后，预初始化会暂停，管理器可能显示“多次启动未完成，预初始化已暂停”。
- 暂停的目的，是避免每次启动都重复同一条可能卡死的路径。
- 处理时应禁用最近改动或最可疑的模块，而不是把暂停提示当作普通缓存错误反复重启。

## 按阶段恢复

### 启动动画前失败

这类故障应优先按启动镜像处理。确认安装时实际修改的分区，然后使用与设备型号、Android 构建、内核版本和槽位匹配的原厂镜像恢复。

```file-tree title="安装方式与常见恢复目标"
启动链
├── LKM
│   ├── 有 init_boot 且 KMI 非 android12-* → 原厂 init_boot
│   ├── 没有 init_boot 或 KMI 为 android12-* → 原厂 boot
│   └── 安装时手动选择 vendor_boot → 原厂 vendor_boot
└── Built-In
    └── 通常 → 原厂 boot
```

最终以管理器安装页、安装日志或实际刷写命令为准。`boot`、`init_boot` 和 `vendor_boot` 不是可以互相替代的通用分区。

::: danger A/B 设备要确认当前槽位

只处理实际被修改的槽位。不要为了“保险”同时刷两个槽位，也不要在 OTA 已合并或两个槽位版本不一致时盲目切换活动槽位。完整操作见[救砖](/guide/rescue-bootloop/)。

:::

### 启动动画循环

如果能够进入启动动画，先尝试 FinaSU 安全模式。进入系统后：

:::: steps

1. **保留当前状态**

   记录安全模式、最近安装的模块、挂载提供者、FolkZygisk/Sui 状态和时间点。先不要清空 `/data/adb`。

2. **逐个恢复模块**

   先只启用一个模块并重启。模块文件、`post-fs-data.sh`、`service.sh`、元模块和受管 `.ko` 都可能阻塞或破坏启动。

3. **检查预初始化警告**

   如果预初始化已暂停，先处理对应模块。不要通过删除多份状态文件强迫它在同一坏配置上重试。

4. **恢复最小能力集合**

   暂时关闭 Folk Mount、NoMount、FolkZygisk、Sui 和 UTS View 等非必要能力。确认基础 Root 和系统启动稳定后，再按依赖逐个开启。

::::

如果安全模式仍然无法进入，按启动镜像路径恢复。不要只删除某个模块目录后就认定问题已经解决；模块可能已经修改了启动早期配置或参与内核模块加载。

### 能进系统但界面反复崩溃

这类问题通常不是启动镜像损坏。优先检查：

- 最近安装或更新的模块是否修改了系统界面依赖；
- 目标应用的 App Profile 是否限制了 UID、GID、SELinux 或命名空间；
- NoMount 例外与“卸载模块”是否让应用看到了错误的文件视图；
- Zygisk 模块是否只支持单一 ABI；
- Sui 的应用权限、后台通知或管理器身份是否异常。

对应排查入口见[驱动运行异常](/troubleshoot/runtime/)和[检测与隐藏](/troubleshoot/detection/)。

## 什么时候必须救砖

出现以下任一情况时，不要继续依赖管理器内操作：

- 无法进入系统，也无法通过安全模式恢复；
- 刷入后连 Recovery 或 Fastboot 都无法进入；
- 设备持续重启，来不及完成按键流程；
- 已确认写入了错误分区、错误槽位或明显不匹配的内核镜像；
- 启动日志显示内核 panic、模块 vermagic 错误或根文件系统无法挂载。

此时按[救砖](/guide/rescue-bootloop/)确认 Fastboot、Recovery 和厂商官方恢复路径。不要随意使用来源不明的 EDL、Firehose 或“一键救砖”工具。

## 恢复后怎样验证

:::: steps

1. **先确认系统本身可启动**

   恢复原厂镜像后，至少完成一次正常系统启动，再重新安装 FinaSU。

2. **核对设备事实**

   重新记录型号、Android 构建、完整内核版本、KMI、ABI、当前槽位和启动分区。见[设备兼容性](/troubleshoot/compatibility/)。

3. **使用最小安装**

   首次恢复后只安装 FinaSU 与匹配管理器，不立即恢复全部模块和隐藏设置。

4. **逐项恢复**

   先验证 Root，再验证一个普通模块，最后验证 Zygisk、Sui、NoMount 等依赖能力。

5. **保存日志**

   如果问题复现，保留“发送日志”导出的压缩包和相关启动日志，再按[提交问题报告](/troubleshoot/report/)提供时间线。

::::
