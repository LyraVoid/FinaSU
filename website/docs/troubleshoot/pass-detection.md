# 过检测

<Badge text="目标应用优先" type="tip" /> <Badge text="不要追求全绿" type="warning" />

过检测的目的是让日常应用正常工作，不是让所有检测工具都显示绿色。检测工具会主动寻找 Root、注入、挂载和完整性异常，强度通常高于普通应用；检测工具报红也不代表 FinaSU 已经损坏。

## 先判断是否需要继续

:::: table 两种情况

| 现象 | 建议 |
| --- | --- |
| 日常应用功能正常，只有检测工具报红 | 一般不需要继续处理 |
| 某个应用明确拒绝启动、登录或支付 | 记录应用名、提示和最近一次改动，再做排查 |

::::

如果应用本身能用，不要为了检测工具的全绿结果继续加隐藏项。越是专门检测 Root 的工具，越可能故意检查极端特征，过不了并不奇怪。

## 不要堆隐藏方案

隐藏项不是越多越好。多个来源不明的隐藏包可能争抢同一套内核接口，最后 Root 授权、模块挂载或其他正常应用反而先坏掉。

不要同时打开全部隐藏选项，也不要把“一键过检测”当成万能修复。保持最小配置，出现问题才能知道是哪一项造成的。

## 最小处理顺序

:::: steps

1. **先保持可用配置**

   移除近期新增的非必要隐藏项和来源不明的包。先确认 FinaSU 的 Root 授权与模块本身正常。

2. **确认目标应用是否获得了 Root**

   已允许 Root 的 UID 不会继续套用非 Root Profile 的模块卸载策略。先看 App Profile，不要盲目调整挂载。

3. **只改与现象相关的一项**

   模块可见、挂载记录、SELinux 差异和内核能力属于不同层面。一次只调整一项，避免同时改变多个变量。

4. **重新启动目标应用**

   先彻底关闭并重新打开应用；如果改动要求重启设备，再完整重启后复测。

5. **恢复正常后立即停止**

   目标功能已经可用就不要再追检测工具的分数。继续叠加设置通常只会增加冲突和排查难度。

::::

::: warning 不要长期关闭 SELinux 强制模式

把 SELinux 设为 Permissive 会降低系统安全边界，也不保证通过检测。只能在明确排错或受控流程中临时使用。

:::

::: warning 别把全绿当成目标

如果你的软件可以正常使用，请不要纠结于检测软件。

==过生活，别过检测。==

:::

目标应用仍然拒绝时，按[检测与隐藏](/troubleshoot/detection/)确认它实际能看到什么，再选择对应的一层处理。
