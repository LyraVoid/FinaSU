# 验证

<Badge text="设置入口 6/8" type="info" /> <Badge text="管理器应用锁" type="tip" />

“验证”用于确认操作管理器的人是设备持有人。它与 Root 授权、Android 锁屏和 SELinux 都不是同一套机制。

::: tip 进入方式

打开管理器 → 设置 → 点第二行第三个 **验证**。

:::

## 它保护什么

验证只保护 FinaSU 管理器中的敏感入口和操作。它不会：

- 替代设备锁屏。
- 阻止其他 Root 应用执行命令。
- 修改应用的 Root 白名单。
- 加密 `/data/adb` 中的模块或授权文件。

它的价值是：即使别人拿到了已经解锁的手机，也不能直接打开管理器、安装模块或刷写分区。

## 先设置凭据，再选择默认方式

页面先提供“数字密码”和“图案”两个凭据，再提供“默认验证方式”。

### 数字密码（PIN）

- 只能是 4 位或 6 位数字。
- 未设置时显示“设置数字密码”。
- 已设置时显示“修改数字密码”和“清除数字密码”。
- 修改或清除前必须验证当前密码。

### 图案

- 至少连接 4 个点。
- 不能重复经过同一个点。
- 未设置时显示“设置图案”。
- 已设置时显示“修改图案”和“清除图案”。
- 修改或清除前必须验证当前图案。

### 默认验证方式

默认方式有四种：

::: table 验证方式

| 方式 | 使用条件 | 说明 |
| --- | --- | --- |
| **无** | 无 | 不验证，所有保护目标都等于关闭 |
| **指纹** | 设备具备强生物识别硬件并已录入 | 界面文案显示“指纹”，实际由 Android 强生物识别 API 处理 |
| **数字密码** | 已设置 PIN | 使用 4 位或 6 位数字密码 |
| **图案** | 已设置图案 | 使用至少连接 4 个点的图案 |

:::

如果选择数字密码或图案但尚未设置对应凭据，管理器会拒绝更改并提示先设置凭据。生物识别硬件缺失或未录入时，“指纹”选项不会出现。

::: important 默认方式会应用到所有已保护目标

当前页面采用“统一默认方式”：打开某个目标的保护开关后，它使用默认验证方式。将默认方式改为“无”也会使所有已保护目标失去实际拦截。

:::

## 保护目标

可以分别开启以下保护：

::: table 敏感操作

| 目标 | 触发时机 | 开启后 |
| --- | --- | --- |
| **应用启动** | 每次进入管理器 | 启动后先显示验证页 |
| **模块安装** | 从本地、仓库或刷写流程安装模块 | 安装前要求验证 |
| **模块卸载** | 删除模块 | 卸载前要求验证 |
| **模块禁用** | 关闭模块开关 | 禁用前要求验证 |
| **分区刷写** | 修补、刷入或恢复启动分区 | 写入前要求验证 |
| **主题 / FPT 导入** | 导入 `.fpt` 主题包 | 应用主题资源前要求验证 |
| **重启操作** | 管理器发起重启、软重启或相关恢复操作 | 执行前要求验证 |

:::

::: warning 分区刷写的风险最高

“分区刷写”保护不能替代备份、镜像匹配和救砖准备。验证只确认操作者身份，不会检查镜像是否属于当前设备或槽位。

:::

## 第一次配置

:::: steps

1. **设置凭据**

   选择“设置数字密码”或“设置图案”，按提示输入两遍。至少准备 PIN 与图案中的一种。

2. **选择默认验证方式**

   返回分类首页，在“默认验证方式”中选择刚设置的 PIN 或图案；设备支持时也可以选择指纹。

3. **逐个开启保护**

   建议先开启“应用启动”，再加“模块安装”“模块卸载”“分区刷写”和“重启操作”。

4. **退出并验证**

   完全退出管理器，再重新打开，确认验证页出现并且能够正常通过。

5. **记录恢复方法**

   记住 PIN 或图案。忘记后不能靠重装 APK 绕过；若凭据存储损坏，页面会进入不可编辑状态，需要先处理数据问题。

::::

## 修改与清除

- **修改 PIN**：验证旧 PIN，再输入新的 4 位或 6 位数字。
- **修改图案**：验证旧图案，再重新连接。
- **清除 PIN/图案**：必须先通过旧凭据验证。
- 清除当前默认方式所依赖的凭据后，相关保护会降级为“无”，避免留下无法完成的验证。

::: danger 不要在不清楚数据位置时手动删除安全配置

直接删除管理器的 SharedPreferences 或应用数据，可能让你失去现有保护配置，也可能影响其他管理器状态。先导出日志并确认恢复路径。

:::

## 凭据怎样保存

管理器不会保存 PIN 或图案原文。凭据使用带随机盐的 PBKDF2-HMAC-SHA256 记录校验，只保存派生结果。连续验证失败后，重试会被逐步延迟。

如果页面提示存储异常：

- 所有验证设置会变为不可编辑。
- 不会把损坏记录当成“尚未设置密码”。
- 管理器继续按保护状态处理敏感操作，而不是静默放行。

这种情况下先备份可访问的数据，再排查应用存储或恢复导入的配置。

## 推荐配置

::: table 按使用强度选择

| 使用场景 | 建议 |
| --- | --- |
| 个人设备，频繁调试 | 应用启动 + 模块安装 + 分区刷写 |
| 日常主力机 | 应用启动 + 模块安装 / 卸载 / 禁用 + 重启 |
| 经常测试主题 | 再开启“主题 / FPT 导入” |
| 借给他人临时使用 | 至少开启应用启动，并关闭 ADB Root |
| 越狱模式 | 保留重启保护；自动越狱仍需自启动权限 |

:::

## 验证流程

::: timeline 一次敏感操作

- 在管理器中触发受保护操作
  time=开始

- 管理器读取该目标是否受保护和当前默认方式
  time=检查

- 显示指纹、PIN 或图案验证
  time=验证

- 验证通过后继续原操作；取消或失败则停止
  time=结果 type=success

- 操作本身是否成功仍由模块、内核和存储状态决定
  time=后续

:::

::: info 验证通过不等于操作一定成功

应用锁只负责拦住未验证的人。镜像不匹配、模块 ZIP 损坏、存储空间不足或内核拒绝写入时，操作仍会失败。

:::

## 常见问题

:::: collapse accordion

- **忘记 PIN 或图案怎么办？**

  设置页没有绕过入口。先确认是否还能使用另一凭据或仍处于已登录会话；否则需要在不破坏其他数据的前提下处理管理器数据。

- **为什么没有“指纹”选项？**

  设备可能没有强生物识别硬件、尚未录入指纹，或当前系统无法使用强生物识别。

- **设置应用启动后，每次切换应用都要验证吗？**

  取决于管理器是否把这次进入视为新的启动保护会话。完全退出再打开最能稳定复现。

- **关闭默认验证方式后，保护目标还在吗？**

  目标开关可能仍显示受保护，但默认方式为“无”时不会实际拦截。需要重新选择有效凭据。

- **Root 应用能绕过应用锁吗？**

  能直接修改设备数据的 Root 应用不在这套应用锁的安全边界内。验证主要防止普通持有者在管理器界面内直接操作。

::::
