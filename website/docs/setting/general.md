# 通用

<Badge text="设置入口 1/8" type="info" /> <Badge text="更新不是刷内核" type="warning" />

“通用”放的是日常维护会用到、但不属于外观或 Root 运行策略的选项。它目前包含四个功能：检查更新、检查模块更新、App Profile 模板和应用语言。

::: tip 进入方式

打开管理器 → 设置 → 点第一行的 **通用**。

:::

## 检查更新

**检查更新**控制管理器在启动后是否自动检查 FinaSU 的新版本。

- 开启时：管理器刷新首页时会请求正式发布信息；有新版时显示可用的更新入口。
- 关闭时：不会自动发起这项检查，首页也不会显示自动检查得到的版本更新卡。
- 新版本仍应采用官方来源和一致签名，不要因为版本号更高就安装来源不明的 APK。

::: danger “管理器更新”不等于“驱动更新”

管理器 APK 只替换界面和随包资源。LKM、Built-In 与越狱模式的驱动更新方式不同；只更新 APK，不会自动替换已经加载或已经编入内核的驱动。

完整步骤见 [更新 FinaSU](/guide/update/)。

:::

## 检查模块更新

**检查模块更新**决定管理器是否根据模块仓库元数据检查已启用模块的新版本。

- 它检查的是普通模块，不是 FinaSU 管理器本身；停用的模块不会进入这项检查。
- 模块作者没有提供可靠版本号、仓库信息不完整或模块不在已知仓库时，可能不会出现更新提示。
- 看到更新后，先读模块发布说明和兼容范围，再决定是否安装。

:::: steps

1. **确认来源**

   模块更新应来自该模块配置的仓库或其他可信来源，不要从聊天群转发的不明 ZIP 覆盖安装。

2. **先备份**

   可在“设置 → 备份”开启刷写前备份，并保存当前模块与授权列表。

3. **更新后重启**

   模块文件替换通常要等重启后的挂载阶段才真正生效。更新成功提示只表示安装流程完成。

4. **验证结果**

   重启后查看模块状态、SU 日志和相关功能。模块导致无法开机时，按 [救砖](/guide/rescue-bootloop/) 处理。

::::

## App Profile 模板

**App Profile 模板**用于保存可复用的 Root Profile 参数，减少为每个应用重复填写 UID、用户组、capabilities 和 SELinux 域的工作。

::: tip 普通用户直接使用预设

模板页面会提供已加载的本地与在线预设。不了解 UID、GID、用户组、capabilities 和 SELinux 域时，==直接选用需要的预设即可，不需要自定义或新建模板==。

:::

::: warning 模板会改变权限边界

模板不是普通的外观预设。错误的 UID/GID、用户组、SELinux 域或 capability 组合，可能让应用获得过多权限，也可能让应用无法正常工作。只导入可信来源的模板。

:::

模板通常包含以下字段：

:::: field-group

::: field 标识与说明
@type `必填`
@default `名称 / 描述`
用可辨认的名称说明模板用途，例如“普通应用 Root”或“仅文件管理”。描述应写清适用范围。
:::

::: field UID / GID
@type `身份`
@default `按需`
决定 Root 进程运行时的用户与组身份。不是所有应用都需要改；保持默认通常比猜测数值安全。
:::

::: field 用户组
@type `权限`
@default `按需`
附加组会扩大进程可访问的设备或文件范围。不要为了“权限更完整”而盲目加入全部组。
:::

::: field capabilities
@type `细粒度`
@default `按需`
允许在普通身份下保留部分高权限能力。应与应用实际用途匹配。
:::

::: field SELinux 域
@type `强制访问控制`
@default `按需`
决定 Root 进程可执行的操作范围。域填错可能直接导致拒绝访问。
:::

::: field `no_new_privs`
@type `限制`
@default `按需`
禁止进程通过执行文件继续获得额外权限。开启前要确认应用不依赖 `su` 或 setuid 行为。
:::

::::

### 使用模板

:::: steps

1. 进入“设置 → 通用 → App Profile 模板”。
2. 从预设列表中选择符合用途的模板。普通用户做到这一步即可。
3. 在应用的 App Profile 配置中选用该模板。
4. 只有明确理解各权限字段时，才创建或修改模板；保存前自行确认哪些应用正在使用它。

::::

应用级 Root 授权与模板之间的关系见 [App Profile](/manager/app-profile/)。

## 语言

**语言**只改变 FinaSU 管理器界面使用的语言。

::: tip 切换后立即生效

选择语言后，管理器会立即重建当前界面并加载对应语言资源，属于热更新；不需要重启管理器，也不需要重启设备。

:::

可选语言共 20 项，顺序与管理器一致：

| --- | --- |
| 跟随系统 | `default` |
| English | `en` |
| Polski | `pl` |
| Bahasa Indonesia | `in` |
| Русский | `ru` |
| Tiếng Việt | `vi` |
| Português (Brasil) | `pt-BR` |
| Español | `es` |
| العربية | `ar` |
| Türkçe | `tr-TR` |
| 日本語 | `ja` |
| 한국어 | `ko` |
| 简体中文 | `zh-CN` |
| 繁體中文 | `zh-TW` |
| 猫娘 | `zh-AG` |

:::

“跟随系统”会清除管理器自己的语言覆盖，重新使用 Android 系统为应用选择的语言。手动选择只影响管理器，不修改系统语言、模块脚本环境或第三方应用。

::: tip 不要靠语言设置排查模块问题

模块脚本输出、内核日志和 `ksud` 文本通常使用英文。切换管理器语言不会翻译这些内容，也不会改变命令参数。

:::

## 常见问题

:::: collapse accordion

- **关闭“检查更新”后，还能手动检查吗？**

  可以。重新打开开关会重新启用启动检查；是否需要立即检查取决于当前版本的更新入口。

- **为什么模块没有更新提示？**

  该模块可能没有可靠的版本元数据、没有配置仓库，或已安装版本无法与仓库条目对应。也可以手动打开模块仓库查看。

- **为什么管理器版本更新了，首页仍显示旧的运行方式？**

  运行方式来自当前驱动，不是 APK 自己声明的值。内置或 LKM 驱动要按对应更新路径处理。

- **改了管理器语言，为什么日志仍是英文？**

  日志由内核、`ksud` 或模块产生，不属于管理器界面的本地化范围。
