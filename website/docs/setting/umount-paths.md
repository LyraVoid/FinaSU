# 自定义卸载挂载点

<Badge text="按 UID 生效" type="warning" /> <Badge text="只影响新启动的应用进程" type="tip" />

这个功能用来让**指定 App** 在下次启动时看不到某个**精确挂载点**。它改变的是目标应用自己的 mount namespace，以及应用读取到的真实文件内容。

::: warning 它不是“隐藏挂载记录”

[隐藏挂载记录](/setting/hiding/)只过滤应用读取 `/proc` 时看到的文本；本功能会从目标 App 的真实挂载视图里移除指定挂载点。两者需要分别判断，不能互相替代。

:::

## 适用场景

当某个模块把文件挂载到固定路径，而你只希望某一个目标 App 看到原厂内容时，可以使用本功能。

例如：

- 模块向系统证书目录注入内容，但目标检测 App 应读取原厂目录；
- 某个 App 需要避开特定精确挂载点；
- 排查应用行为是否由某个模块挂载引起。

本功能不是模块管理器的替代品。它只处理你明确填写的挂载点，不处理普通文件、子目录、通配符或正则表达式。

## 生效前提

以下四项必须同时满足：

::: table 生效检查

| 检查项 | 在哪里确认 |
| --- | --- |
| “卸载模块（总开关）”已开启 | [设置 → 功能](/setting/function/) |
| 目标 UID 的 App Profile 允许卸载模块 | [App Profile](/manager/app-profile/)；未单独设置时由“默认卸载模块”决定 |
| 路径是目标 namespace 中的挂载点根 | 只能填挂载点本身，不能填其中的文件或子目录 |
| 目标 App 在规则生效后重新启动 | 已经运行的进程不会立即变化 |

:::

::: important Root UID 不一定执行非 Root 卸载

内核先判断 UID 是否应执行模块卸载。已经获得 Root 的 UID，或 App Profile 不允许卸载模块的 UID，不会因为本页添加了路径就执行卸载。

:::

## 添加规则

:::: steps

1. 打开 **管理器 → 设置 → 功能 → 自定义卸载挂载点**。

2. 点右上角 **添加**，或点空状态里的“还没有自定义规则”。

3. 在“完整挂载点路径”中填写路径，例如：

   ```text
   /system/etc/security/cacerts
   ```

4. 点 **保存规则**。管理器会先保存持久化配置，再尝试把路径加入当前内核列表。

5. 强制停止目标 App，再重新打开。设备不需要因此重启，但已经运行的进程不会即时改变。

::::

添加成功后，页面会从 ksud 和内核重新读取列表，不会用本地数据假装已经生效。

## 路径应该怎么填

正确路径必须：

- 以 `/` 开头；
- 指向挂载点本身；
- 不超过 255 字节；
- 不以 `/` 结尾；
- 不包含空段、`.`、`..` 或控制字符；
- 不是 `/`、`/data`、`/system`、`/apex` 等受保护根级挂载点。

::: table 正确与错误示例

| 写法 | 结果 |
| --- | --- |
| `/system/etc/security/cacerts` | 正确，精确挂载点 |
| `system/etc/security/cacerts` | 错误，不是绝对路径 |
| `/system/etc/security/cacerts/` | 错误，末尾多了斜杠 |
| `/system/etc/security/cacerts/example.0` | 不是挂载点根，不能靠它递归卸载父目录 |
| `/system/*` 或正则表达式 | 不支持 |

:::

移除方式固定使用 **安全延迟移除（MNT_DETACH）**。页面没有 flags 输入框，因为这里不是可调参数面板；固定方式可以在有其他进程正在使用挂载点时安全移除。

## 我的规则与模块自动添加

页面会分开显示不同来源：

::: table 条目来源

| 分组 | 来源 | 能否在这里删除 |
| --- | --- | --- |
| **我的规则** | 你在本页保存的配置 | 可以 |
| **模块自动添加（只读）** | 模块或其他外部组件写入内核的条目 | 不可以 |
| **来源未知（只读）** | 无法可靠判断来源的条目 | 不可以 |

:::

管理器不会为了“看起来干净”而乐观删除未知条目。没有来源信息时，它会保持只读。

## 删除规则后为什么还可能生效

删除操作只移除你的持久化配置，不会强行删除本次开机中可能由模块或其他来源注册的内核条目。

- 删除后，本次开机内已经存在的内核条目仍可能继续生效；
- 重启后，如果没有模块再次注册该路径，它才会完全停止；
- 模块自动添加的条目不会因为“删除全部自定义规则”而消失。

因此页面在删除确认中会明确提示：==本次开机仍可能生效，重启后停止==。

## 验证是否生效

:::: steps

1. 记录目标 App 的 UID，并确认它的 App Profile 允许卸载模块。

2. 关闭目标 App。只切到后台不算完全重启。

3. 重新打开目标 App，再执行实际业务操作或使用检测 App。

4. 如果应用仍然看到挂载内容，按[常见问题](#常见问题)逐项排查。

::::

熟悉命令行的用户可以在目标进程启动后检查它自己的挂载视图：

```bash
adb shell pidof <包名>
adb shell su -c "grep ' /你的/挂载点 ' /proc/<PID>/mountinfo"
```

没有匹配行表示该挂载点不在这个进程的 namespace 中。仅修改 `/proc` 显示不会影响这个判断。

## 常见问题

::: collapse accordion

- **添加后为什么没有立刻变化？**

  目标 App 已经运行。强制停止后重新打开；设备本身通常不需要重启。

- **为什么已经开了总开关，目标 App 还是能看到？**

  检查目标 UID 的 App Profile 是否允许卸载模块，并确认 UID 没有因为 Root 授权而跳过非 Root 卸载策略。

- **为什么路径明明存在却没有效果？**

  路径必须正好是目标 namespace 中的挂载点根。挂载点里的普通文件、子目录和父目录都不能代替它。

- **页面显示“当前内核不支持读取挂载点列表”怎么办？**

  这表示当前内核没有新的只读枚举命令。已保存的规则仍可能通过旧的新增命令生效，但管理器无法确认内核是否接受，因此不能把这个状态当作“已生效”。

- **页面显示“无法读取自定义规则”怎么办？**

  配置文件可能损坏或不可读。管理器不会自动重建或覆盖原文件，并会禁止写入。先备份并检查配置，不要直接删除。

- **它能代替“隐藏挂载记录”吗？**

  不能。本功能改变真实挂载和文件内容；“隐藏挂载记录”只改变 `/proc` 文本视图。

- **能对目录下所有内容递归卸载吗？**

  不能。本功能只接受精确挂载点，不支持目录递归、通配符、正则和自动推荐。

:::

## 安全建议

- 先在一个不重要、可随时清除数据的目标应用上验证。
- 不要卸载核心系统挂载点，也不要把根级目录当作测试路径。
- 不要只凭“应用检测正常”判断：同时检查业务功能是否仍正常。
- 修改前记录目标包名、UID、原路径和应用当前表现。
