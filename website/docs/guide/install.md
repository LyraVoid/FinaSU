# 安装与刷写

安装页面会按设备状态显示可用方式。开始前先备份原厂镜像，并确认镜像与当前系统版本一致。

## 选择文件并修补

用于首次安装或手动恢复流程：

1. 选择由管理器提示的分区镜像。
2. 必要时选择内置 LKM 的 KMI；只有 `.ko` 文件可以作为本地 LKM。
3. 可勾选“备份为原厂镜像”，仅在所选文件确实是原厂镜像时使用。
4. 修补完成后，用 `fastboot` 或设备对应的刷写方式写入同一分区。

Android 13 及以后把通用 ramdisk 拆到独立分区的设备，通常会修补 `init_boot`；其他设备可能修补 `boot`。始终以管理器识别出的分区为准。

## 下载文件并修补

输入完整 OTA 包或 factory 镜像的地址。管理器会检查包内可用的启动分区，再执行与“选择文件”相同的修补流程。

## 直接安装

设备已有可用的 Root 时，管理器可以直接修补并刷写当前设备。这是升级 FinaSU 的常用方式。安装前建议开启“刷写前备份”。

## 安装到未使用的槽位

该方式只用于 A/B 设备完成 OTA、尚未重启的时刻。确认后会强制在下次重启切换到另一个槽位，不应在普通重启时使用。

## 使用本地 LKM 文件

修补流程可以配合一个与当前 KMI 匹配的 `.ko` 文件。文件不匹配会导致驱动无法加载；没有把握时使用管理器随包提供的驱动。

## AnyKernel3

AnyKernel3 ZIP 会以 Root 权限运行安装器，并由安装器决定写入哪些分区和槽位。FinaSU 不会在刷入后修正槽位或刷新 `ksud`。安装成功不保证设备可以启动，已有启动镜像备份也未必覆盖安装器修改的全部分区。

::: danger
只刷入来源可信、明确支持当前设备与系统版本的 AnyKernel3 包，并准备可用的恢复镜像。
:::

## 刷写选项

- **允许 Shell**：允许通过 Root Shell 使用 `su`。
- **启用 ADB Root**：为安装流程开启调试入口。
- **刷写前备份**：在覆盖前保存当前模块或分区快照。

刷写完成后重启，回到管理器确认驱动与 Root 状态。
