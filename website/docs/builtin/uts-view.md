# UTS View

<Badge text="内核特性" type="info" /> <Badge text="新进程生效" type="warning" /> <Badge text="最多 128 个应用" type="tip" />

==UTS View 让目标进程看到另一组 `uname` 信息==。它修改的是 Linux UTS namespace 中的名称字段，不是 Android 系统属性，也不是完整的设备指纹。

::: important 只影响 `uname` 一类字段

UTS View 不会修改 `ro.build.*`、安全补丁级别、硬件认证、CPU 实际能力或应用私有缓存。应用仍可能通过其他接口得到真实信息。

:::

## 入口与页面

入口在 **设置 → 功能 → 内核信息伪装**。页面从上到下分为：

1. 启用状态与当前伪装来源。
2. 生效范围：选定应用或全局。
3. 伪装字段与目标应用。
4. 运行详情。
5. 恢复或删除设置。

当 SUSFS 正在提供 `uname` 伪装时，页面会显示“由 SUSFS 接管”，普通编辑控件会受限制。需要使用“改用本功能伪装”完成显式交接。

## 六个字段

:::: field-group

::: field 系统名（sysname）
@type `默认 hidden`
通常是 `Linux`。一般不需要单独修改。
:::

::: field 节点名（nodename）
@type `默认 hidden`
主机名。一般不需要单独修改。
:::

::: field 内核版本（release）
@type `常用`
例如 `6.1.75-android14`。多数场景只需要改这一项。
:::

::: field 构建版本（version）
@type `常用`
内核构建字符串，通常包含编译器或构建时间信息。
:::

::: field 机器架构（machine）
@type `默认 hidden`
例如 `aarch64`。与应用 ABI 明显不一致时可能引发兼容性问题。
:::

::: field 域名（domainname）
@type `默认 hidden`
少数环境会读取该字段。
:::

::::

每个字段最多 64 字节，不能包含 NUL；`release` 还要求全部字符是可打印 ASCII 或空格。只有进入伪装掩码的字段会被覆盖，未选择的字段继续保留目标进程原来的值。

::: warning 字段必须彼此自洽

不要拼出明显矛盾的版本、构建时间和架构组合。伪装的目标是替换身份信息，而不是制造一个应用无法解析的内核版本。

:::

## 两种生效范围

::: table 选定应用与全局

| 范围 | 命中对象 | 目标上限 | 实现方式 |
| --- | --- | --- | --- |
| **只让选中的应用生效** | 应用 UID 在列表中的普通应用进程 | 128 个 UID | 在应用启动、切换 UID 时创建私有 UTS namespace 并写入模板 |
| **所有应用和终端** | 仍使用初始 UTS namespace 的进程 | 不使用应用列表 | 修改初始 UTS namespace 的名称字段 |

:::

选定模式只对应用进程生效。非应用进程、隔离进程、已有私有 UTS namespace 的进程会被跳过，并计入运行详情。

全局模式看起来范围更大，但也不是“重写所有 namespace”。已经创建私有 UTS namespace 的容器、应用或系统进程不会被追溯修改，通常需要重新启动才会进入新的初始视图。

::: danger 全局模式影响面很大

切换全局前，管理器会要求确认。所有共享初始 UTS namespace 的进程都会看到新值。不要把错误的 `release`、`machine` 或缺失字段应用到整机。

:::

## 启用流程

:::: steps

1. **确认当前来源**

   如果由 SUSFS 接管，先决定继续使用 SUSFS，还是执行“改用本功能伪装”。

2. **以当前值作为起点**

   能读取真实值时，优先使用“使用本机当前信息作为起点”，再只修改必要字段。

3. **选择范围与目标**

   普通场景选择“只让选中的应用生效”，最多选择 128 个 UID。全局模式只用于确有需要的测试或设备级伪装。

4. **先保存，再启用**

   未启用时保存的是草稿；启用时保存并立即应用模板。已有目标进程不会自动改变。

5. **彻底关闭并重开目标应用**

   多进程应用要结束所有相关进程。只切到后台不保证创建新的应用进程。

6. **查看运行详情**

   “已经生效”只说明内核观察到目标进程命中。如果应用仍显示旧值，先确认应用没有缓存结果。

::::

## 状态含义

::: table UTS View 页面状态

| 状态 | 含义 |
| --- | --- |
| **未设置** | 没有保存字段或目标 |
| **设置已保存，但还没生效** | 草稿存在，功能未启用 |
| **伪装已开启** | 模板已启用，但还没有观察到目标应用命中 |
| **已经生效** | 至少一个目标进程已通过检查并采用模板 |
| **已对所有应用生效** | 全局模板已启用 |
| **由 SUSFS 接管** | SUSFS 当前是 `uname` 提供者，UTS View 不能直接抢占 |
| **当前内核不支持** | 缺少必要符号或内核特性 |
| **伪装状态异常** | 配置、内核、提供者或运行日志有错误 |

:::

状态不是单纯由开关决定。页面还会读取内核回读、当前 UTS provider、持久配置和最近运行错误。

## 与 SUSFS 的关系

SUSFS 也可能伪装 `uname`。同一时刻只能有一个明确的活动提供者，否则谁在写入真实内核值会变得不可预测。

::: timeline 从 SUSFS 切换到 UTS View

1. **检测到 SUSFS 已应用或计划应用**

   UTS View 显示“由 SUSFS 接管”，不会直接覆盖。

2. **准备 UTS View 模板**

   页面上的修改先作为草稿保存。

3. **点击“改用本功能伪装”**

   该操作会先恢复 SUSFS 的 `uname` 运行时伪装，再把 UTS View 模板启用。

4. **失败时事务回滚**

   若交接中某一步失败，系统会尝试恢复旧 UTS View 配置、内核状态和 SUSFS 状态，并报告残留。

5. **重新启动目标应用**

   避免旧进程继续持有切换前的 UTS namespace 或缓存值。

:::

当页面显示 SUSFS 接管时，“删除 UTS 设置”只会删除 UTS View 自己的配置，==不会删除或关闭正在生效的 SUSFS 伪装==。

## 运行详情

选定模式会记录以下观察值：

- **命中次数**：成功应用模板的进程数。
- **最近命中**：最近一次 UID 与 PID。
- **不在应用列表**：目标不是所选 UID。
- **非应用进程**：普通应用 UID 检查未通过。
- **非普通应用进程**：不是预期 Zygote 应用启动路径。
- **已有独立运行环境**：进程已有私有 UTS namespace。
- **隔离进程**：WebView 或 SDK 沙箱等隔离 UID。
- **创建隔离环境失败次数**：内核无法为命中目标创建私有 namespace。
- **丢弃过期结果**：模板在操作期间发生变化，旧观察结果没有被误算。

这些计数在重置或重新应用配置时归零。看到“命中”不等于每个应用子进程都命中，尤其是使用独立 namespace 或特殊启动路径的应用。

## 恢复真实信息

未由 SUSFS 接管时，页面底部的“恢复真实信息”会：

- 关闭 UTS View。
- 清空内核模板。
- 删除持久配置和选中的应用列表。

已经运行的应用可能需要重启才能重新读取真实值。由 SUSFS 接管时，只删除 UTS View 自己的设置，不触碰 SUSFS。

## 排错

:::: collapse accordion

### 显示“伪装已开启”但没有命中

先彻底关闭目标应用及其所有进程，再重新打开。然后确认所选 UID 仍然正确；重装应用或更换工作资料后 UID 可能变化。

### 目标应用已有独立运行环境

该进程在 UTS View 介入前就拥有私有 UTS namespace。UTS View 不会追溯改写，应重启应用或相关运行环境。

### 全局模式没有影响某个终端或容器

它只修改初始 UTS namespace。终端、容器或系统服务创建了自己的 UTS namespace 时，可能继续看到原值。

### 页面无法读取真实内核版本

SUSFS 正在接管时会显示“无法读取真实值”。先停止或交接提供者，再重新取值，不要手工猜测。

### 修改后应用行为异常

立即关闭 UTS View 或恢复真实信息，再重启应用。重点检查 `release`、`version` 和 `machine` 是否自洽。

## 配置与诊断位置

```file-tree title="UTS View 相关位置"
/data/adb/ksu
├── uts_view.json               # 字段、范围、目标与启用意图
├── uts_view.runtime_error      # 最近一次启动或应用错误
└── .uts_view.lock              # 配置事务锁
```

配置文件受属主和权限检查保护。不要直接改写 JSON 来绕过字段长度、UID 上限或模式校验。

::: code-tabs

@tab 管理器

```text
设置 → 功能 → 内核信息伪装
查看当前提供者、页面状态、运行详情和错误文本
```

@tab 状态

```sh
/data/adb/ksud uts-view status
```

:::

命令行返回配置、provider、内核状态和观察计数；日常操作仍以管理器为准。

## 使用建议

1. **通常只改 `release` 或 `version`。** 其他字段没有明确需求时保持原样。
2. **优先使用选定应用。** 全局模式的影响面远大于单个应用。
3. **先处理提供者冲突。** SUSFS 接管时不要尝试用两个开关同时启用。
4. **用新进程验证。** 老进程继续使用旧的 name 缓存是正常现象，不代表 UTS View 没有工作。
5. **不要把 UTS View 当完整反检测。** 它只改变 `uname` 字段，不覆盖系统属性和硬件证明。
